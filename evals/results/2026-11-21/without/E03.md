## Design: star schema, not one 60-column table
Only about 20 of the 60 columns are needed to answer the four questions. I would leave out the rest: contact data (`cliente_email`, `cliente_telefone`, `cliente_endereco`, `vendedor_email`), banking (`agencia`, `conta`, `nosso_numero`, `linha_digitavel`, `banco_codigo`, `chave_nfe`), audit (`usuario_*`, `data_cadastro`, `data_alteracao`, `hash_integracao`), `observacao` and the accounting fields. ### Fact: `Titulos` (grain: titulo/parcela)
Keep: `id_titulo`, `parcela`, `id_cliente`, `id_regional`, `id_filial`, `data_emissao`, `data_vencimento`, `data_pagamento`, `valor_original`, `valor_aberto`, `valor_pago`, `status_titulo`, `flag_renegociado`.
Dropped relationship keys: none; descriptive attributes move to dimensions.

### Dimensions
- `Cliente`: `id_cliente`, `cliente_nome`, `cliente_segmento`, `cliente_uf` (and `cliente_classificacao_risco` if wanted). Deduplicated in Power Query (`Table.Distinct` on `id_cliente`) from the view. `cliente_cpf_cnpj` excluded.
- `Regional`: `id_regional`, `regional_nome` (add `Filial` as an optional second level: `id_filial`, `filial_nome`).
- `Calendario`: a real date table (generated, marked as date table), with Year, Month, YearMonth, a sort column and an offset-from-current-month column for "last 24 months".

### Relationships
- `Titulos[id_cliente]` -> `Cliente[id_cliente]` (many-to-one, single direction)
- `Titulos[id_regional]` -> `Regional[id_regional]`
- `Titulos[data_vencimento]` -> `Calendario[Date]` (active, due date drives Q2 and "due" in Q4)
- `Titulos[data_pagamento]` -> `Calendario[Date]` (inactive, activated with `USERELATIONSHIP` for "received")
- `Titulos[data_emissao]` -> `Calendario[Date]` (inactive, optional)

### Measures (table `_Medidas`)
```DAX
Valor Aberto = SUM ( Titulos[valor_aberto] )

Valor Vencido =
CALCULATE (
    [Valor Aberto],
    Titulos[data_vencimento] < TODAY ()
)

Dias Atraso Ponderado =
DIVIDE (
    SUMX (
        FILTER ( Titulos, Titulos[data_vencimento] < TODAY () && Titulos[valor_aberto] > 0 ),
        Titulos[valor_aberto] * ( TODAY () - Titulos[data_vencimento] )
    ),
    [Valor Vencido]
)

Valor Recebido =
CALCULATE ( SUM ( Titulos[valor_pago] ), USERELATIONSHIP ( Titulos[data_pagamento], Calendario[Date] ) )

Valor a Vencer no Mes = SUM ( Titulos[valor_original] )   -- uses active relationship (due date)

Recebido vs Devido % = DIVIDE ( [Valor Recebido], [Valor a Vencer no Mes] )

Valor Vencido Top 20 =
VAR Top20 = TOPN ( 20, ALL ( Cliente[id_cliente] ), [Valor Vencido] )
RETURN CALCULATE ( [Valor Vencido], KEEPFILTERS ( Top20 ) )

% Vencido Top 20 = DIVIDE ( [Valor Vencido Top 20], CALCULATE ( [Valor Vencido], ALL ( Cliente ) ) )
```
Note: Q2's "days past due per month" is only exact with snapshots (point 3 above); the measure above gives today's weighted average and I would refine it after your answer.
