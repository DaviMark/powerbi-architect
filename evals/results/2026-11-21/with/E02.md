**How it will be built**
- The business filter (remove cancelled orders), the renames (friendly aliases) and the types (`CAST`) all go in one T-SQL `SELECT` against `dw.vendas`.
- Power Query gets a single `Fonte` step (`Value.NativeQuery` with server and database as parameters). There is no "Renamed Columns", "Changed Type" or "Filtered Rows" step.
- Only the columns a measure, visual, relationship or filter needs are imported. No `SELECT *`.
- Better still if the DBA can create a view such as `bi.vw_vendas` with this logic. The SQL then becomes a thin `SELECT` from it.

**Template (T-SQL).** The column names and the "cancelled" rule are assumptions, so please confirm them.
```sql
-- @table Fato Vendas
-- @description Sales order lines, excluding cancelled orders
-- @grain 1 row per order line
SELECT
    CAST(v.id_pedido    AS bigint)         AS [id_pedido],
    CAST(v.id_cliente   AS int)            AS [id_cliente],
    CAST(v.id_produto   AS int)            AS [id_produto],
    CAST(v.data_pedido  AS date)           AS [Data Pedido],
    CAST(v.valor_total  AS decimal(18,2))  AS [Receita],
    CAST(v.quantidade   AS int)            AS [Quantidade]
FROM dw.vendas AS v
WHERE v.status <> 'CANCELADO'   -- assumption: confirm the column and the value
```
