Before I write any code: a custom visual (.pbiviz) is the last resort in my workflow. It is software you would have to maintain, certify and upgrade. "Actual vs target by region" is a standard comparison, and native Power BI visuals cover it. I have not built or scaffolded anything.

**Native options, in order of preference**

| Option | What it gives you | Fits when |
|---|---|---|
| Clustered bar, one row per region, sorted, with the target as a reference or constant line | Actual vs target per region | Targets are the same across regions, or you can show them as a second series |
| Bar (actual) plus a target marker (error bar, or a second measure drawn as a marker or line) | A bullet-style chart | Each region has its own target |
| Card or KPI visual with a variance measure, using **small multiples by region** | One mini chart per region with the target line and an arrow | There are few regions (about 12 or fewer) |
| Matrix: Region, Actual, Target, Variance %, with conditional formatting or an SVG measure for a progress bar | Compact, exact, themable | Directors want to read the numbers and see status at a glance |
| Waterfall or decomposition tree | Variance drivers | The question is *why* a region misses target, not *whether* it does |

A bullet chart built from native visuals plus formatting almost always covers this request. I would only propose a .pbiviz if all of the following hold:

- the options above fail on a stated requirement (for example a specific bullet layout with qualitative bands that formatting cannot produce),
- no certified AppSource visual allowed by your tenant solves it,
- you accept an owner for maintenance.

In that case I would write an ADR first (comparison, accessibility, security, cost). I would then start from the verified `templates/pbiviz-bullet-kpi` (actual vs target per category) in this skill. It already has `privileges: []`, no network access, keyboard support, high contrast, tooltips and localization.

**Questions (they change the design)**

1. What business question is this page answering? For example "Which regions are below target this month, and by how much?"
2. Where do actual and target live? Same fact table, or two tables (for example a monthly budget fact and a daily sales fact)? What is the grain of each? Different grains mean I share the date and region dimensions between two facts.
3. How is the target defined: one number per region and period, a percentage, or a fixed value for all regions? Is it additive across periods?
4. How many regions, and which period grain (month, quarter, YTD)? This decides between small multiples and a single sorted bar.
5. Is there a company visual identity or theme I should apply? Is any requirement you already know about the native options (for example a specific bullet layout) the reason you are asking for a custom visual?

Once you answer, I will draft the design (grain, measures `Realizado`, `Meta`, `Atingimento %`, `Variação vs Meta`, with descriptions, formats and display folders) and the page wireframe for your approval. Only after you approve will I build anything.
