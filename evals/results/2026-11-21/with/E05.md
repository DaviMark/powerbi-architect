I wouldn't use a pie for 9 categories. Slices that small can't be compared by eye, the labels collide, and the reader can't see which category leads. A pie only works for 2 or 3 parts of a whole.

**What I would build instead (native visual, no custom visual needed)**

**Horizontal bar chart, sorted by value descending**
- Axis: `Category`. Value: `Revenue`. Sort descending, so the leader is on top and drawn in the darkest brand tone.
- Data labels show the share as well as the value (using the measure below). Turn off the value axis, gridlines and legend.
- Title as a sentence, for example: "Three categories generate 70% of revenue" (a dynamic title measure, so it stays true as data changes).
- Other categories in a lighter tone or grey, so the eye goes to the leaders.

```tmdl
/// Share of the selected revenue that each category represents, among the categories currently shown.
measure '% do Total' = DIVIDE ( [Receita], CALCULATE ( [Receita], ALLSELECTED ( 'Dim Produto'[Categoria] ) ) )
	formatString: 0.0%
	displayFolder: Indicadores
```
Adjust the table, column and `Receita` measure names to your model. Show `% do Total` in the data labels or tooltip.

**Alternatives if the part-to-whole message is what matters**
- Treemap, if there is a hierarchy (category, then subcategory) and the exact comparison is less important.
- Group the 9 into the top 3 or 4 plus "Others", and then a donut or 100% stacked bar is acceptable (3 parts that sum to 100%).

If so I would group it to at most 3 to 5 slices, label the slices directly and keep the same color for each category on every page. Accessibility: I add alt text with the key takeaway.
